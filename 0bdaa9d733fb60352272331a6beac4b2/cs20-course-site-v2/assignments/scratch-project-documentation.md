# Scratch Project Documentation

**Points:** 4.0
**Submission type:** online upload
**Allowed file types:** txt,rtf,doc,docx

Good documentation is an important component of any computer program; it informs users how to use your software, and makes it possible for other programmers – who might be taking over a project – to understand how it works!

For our class, you can use the following structure when documenting your code:

Basic Instructions and Explanation

In a text document (word, pdf, txt), address the following topics. Be thorough – you should not assume that the user has any background knowledge of your program; your documentation should allow a beginner to successfully understand and operate your software. *As a reference point, this should not be shorter than a page (single spaced), and will be graded according to whether this amount of length was met, and that all five sections below were reflected on appropriately. (250 words +)*

1. **Basic Premise**

Explain what the program is. If it is for productivity, describe how the program will assist the user with a task. If it is a game, describe the type of game and any relevant backstory.

2. **Key Features**

A summary of the different features or capabilities of the program. If applicable, provide a breakdown description of each feature. Explain what the user needs to do to in order to make the program work correctly.

3. **Controls / Game Mechanics**

Provide a listing of the different user input controls. If a user forgets what buttons they need to press on the keyboard or what to click, they should be able to look it up.

4. **Limitations**

If there are known bugs or issues with the program (ways that the user can break the program) that you have been unable to fix, list the problems and potential workarounds.

5. **Personal Comments**

As the author of the program, add a short reflection on the program. 

- What new ideas or challenging aspects of the program did you tackle?
- If you had more time, how would you extend this program?
- Add any other reflections you have on your project.
